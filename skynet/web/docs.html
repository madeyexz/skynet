Skynet Data API · v1

One vessel record, over HTTP

Skynet compares what a ship claims (AIS) with what space observes (satellite radar, RF emissions). Every alert and every report in the app comes from one vessel record. The Data API returns that same record, the same risk score and the same zone events, so you can put Skynet's evidence inside your own underwriting, compliance or claims systems.

Base URL: https://skynet.example. All times are integer epoch seconds (UTC). Responses are JSON. The demo world is illustrative.

Authentication

Send your API key as a bearer token on every request. The x-api-key header also works. Requests without a valid key get 401.

Header
Authorization: Bearer sk_live_skynet_demo

The demo key sk_live_skynet_demo is public and reads the demo world. On the hosted demo, write calls (POST /v1/zones, POST /v1/webhooks) also need the demo admin key in an x-admin-key header; without it they get 401 with "error": "admin_key_required".

GET/v1/vessels/{id}/record

The full evidence record for one vessel: verified (fused) track, what AIS claimed, dark periods, every event including operator actions, the risk score and a fingerprint. Optional from and to (epoch seconds) cut the window.

id
Vessel code (D-04), MMSI or IMO.
from, to
Optional window, epoch seconds. Defaults to the whole record.
curl
curl -H 'Authorization: Bearer sk_live_skynet_demo' \
  'https://skynet.example/v1/vessels/D-04/record?from=1794355200&to=1794384000'
Response · 200

             "flag": "Cook Islands", "type": "tanker", "length_m": 228},
  "from": 1794355200, "to": 1794384000,
  "verified_track": [[1794355200, 24.912, 59.871], "…"],
  "claimed_track":  [[1794355200, 24.912, 59.871], "…"],
  "dark_periods": [{"start": 1794371400, "end": 1794377040, "minutes": 94}],
  "events": [{"id": "E-0012", "type": "dark_period", "t": 1794371400, "severity": "high",

The fingerprint is the sha256 of the canonical JSON (sorted keys, no spaces) of events. Recompute it to prove a record has not changed since it was exported.

GET/v1/vessels/{id}/risk

The current Skynet risk score (0–100) with the reasons behind it. Each reason names the layer it came from: ais, sar, rf, registry, sanctions or fusion.

curl
curl -H 'Authorization: Bearer sk_live_skynet_demo' \
  'https://skynet.example/v1/vessels/D-04/risk'
Response · 200
{
  "vessel_id": "D-04", "score": 87, "level": "high",
  "reasons": [{"text": "AIS off 94 min while radar still saw the hull over Cable A", "points": 35, "source": "sar"}, "…"],
  "as_of": 1794382200
}

GET/v1/zones/{id}/events

Events inside a watch zone, oldest first. Pass since (epoch seconds) to poll for new ones; use webhooks if you would rather be told.

curl
curl -H 'Authorization: Bearer sk_live_skynet_demo' \
  'https://skynet.example/v1/zones/Z-1/events?since=1794375000'

POST/v1/zones

Create a watch zone. A zone is a geometry (corridor around a line, polygon, or a watchlist of vessels), a purpose preset (cable, sanctions, insurance, custom), rules, metrics and recipients. Skynet evaluates it against the record straight away and returns the events, alerts and metrics it found.

On the hosted demo this call also needs x-admin-key: <admin key>.

curl
curl -X POST -H 'Authorization: Bearer sk_live_skynet_demo' -H 'x-admin-key: <admin key>' \
  -H 'Content-Type: application/json' 'https://skynet.example/v1/zones' -d '{
  "name": "Tanker watchlist", "purpose": "sanctions",
  "geometry": {"type": "watchlist", "vessel_ids": ["T-11", "D-04"]},
  "rules": [{"id": "dark_period", "label": "AIS off longer than", "enabled": true, "severity": "high",
             "params": [{"key": "hours", "label": "Longer than", "value": 1, "unit": "h"}]}],
  "recipients": [{"name": "Compliance desk", "channel": "webhook", "min_severity": "medium"}]
}'
Response · 200
{"zone": {"id": "Z-2", "name": "Tanker watchlist", "…": "…"}, "events": ["…"], "alerts": ["…"], "metrics": ["…"]}

POST/v1/webhooks

Register a URL. Every new alert is POSTed to each registered URL (best effort, logged). GET /v1/webhooks/deliveries lists the delivery log.

The URL must be a public http or https host. Localhost, private, link-local and other reserved addresses are rejected with 422, both when you register and again before each delivery; redirects are not followed. On the hosted demo this call also needs x-admin-key: <admin key>.

curl
curl -X POST -H 'Authorization: Bearer sk_live_skynet_demo' -H 'x-admin-key: <admin key>' \
  -H 'Content-Type: application/json' 'https://skynet.example/v1/webhooks' -d '{"url": "https://example.com/skynet-hook"}'

Webhook payload: alert.created

Sent once per alert. data is the same Alert object the app shows.

POST to your URL
{

  "data": {

Use cases

Underwriting

Before you quote a hull or war-risk policy, pull the vessel's risk and its recent record: how often it went dark, whether its AIS position disagreed with radar, and whether it met other ships at sea. Price the behaviour, not just the flag.

curl
curl -H 'Authorization: Bearer sk_live_skynet_demo' 'https://skynet.example/v1/vessels/T-11/risk'

Sanctions screening

A registry check tells you who a ship says it is. Skynet tells you what it did: dark periods, ship-to-ship meetings, identity changes and spoofed positions. Put your counterparties' vessels in a watchlist zone and get a webhook the moment one goes dark.

curl
curl -X POST -H 'Authorization: Bearer sk_live_skynet_demo' -H 'x-admin-key: <admin key>' \
  -H 'Content-Type: application/json' 'https://skynet.example/v1/zones' \
  -d '{"name": "Counterparty fleet", "purpose": "sanctions", "geometry": {"type": "watchlist", "vessel_ids": ["S-17", "D-04"]}}'

Claims

When a cable is cut or a cargo goes missing, reconstruct the voyage from independent sources. The record pairs the claimed AIS track with radar-verified positions for the window you ask for, and the fingerprint lets you show it was not edited after the fact.

curl
curl -H 'Authorization: Bearer sk_live_skynet_demo' \
  'https://skynet.example/v1/vessels/D-04/record?from=1794369600&to=1794380400'
